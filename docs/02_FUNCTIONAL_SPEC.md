# 02. Functional Specification (기능 요구서)

## 개요

Phase 1 MVP의 모든 기능을 모듈 단위로 분해합니다. 각 모듈은 유스케이스, 비즈니스 룰, 예외 처리를 포함합니다.

## 모듈 목록

1. 인증 (Authentication)
2. 측정기 등록 (Instrument Registration) ⭐ 핵심
3. 측정기 자산 관리 (Asset Management)
4. 교정 주기 관리 (Calibration Cycle)
5. 교정 이력 관리 (Calibration History)
6. 알림 시스템 (Notification)
7. 대시보드 및 보고서 (Dashboard & Report)

---

## 모듈 1: 인증 (Authentication)

### 1.1 유스케이스

**UC-1-1: 회원가입**
- 입력: 이메일, 비밀번호, 사업장명, 담당자명, 전화번호
- 출력: 사용자 계정 생성, 사업장(tenant) 생성, 자동 로그인
- 비즈니스 룰:
  - 1 사업장 = 1 tenant (multi-tenancy)
  - 첫 가입자는 자동으로 admin 권한
  - 이메일 인증 필수

**UC-1-2: 로그인**
- 입력: 이메일, 비밀번호
- 출력: JWT 토큰 (Access 1시간, Refresh 30일)

**UC-1-3: 사용자 초대**
- admin이 같은 사업장 내 추가 사용자 초대
- 입력: 이메일, 역할(admin/manager/operator)
- 출력: 초대 이메일 발송

### 1.2 역할(Role) 정의

| 역할 | 권한 |
|---|---|
| admin | 모든 권한 + 사용자 관리 + 결제 |
| manager | 측정기 CRUD + 알림 설정 + 보고서 |
| operator | 측정기 조회 + 사진 등록만 |

### 1.3 예외 처리

- 이메일 중복: "이미 가입된 이메일입니다"
- 비밀번호 8자 미만: "최소 8자 이상 입력해주세요"
- 로그인 5회 실패: 15분 잠금

## 모듈 2: 측정기 등록 (Instrument Registration) ⭐

### 2.1 유스케이스

**UC-2-1: 사진 한 장으로 등록 (핵심)**
- 입력: 측정기 사진 1~3장 (명판 포함)
- 출력: 인식된 정보 + 드롭다운 폼

**상세 시나리오**:
```
1. 사용자가 모바일 앱에서 "사진 등록" 버튼 탭
2. 카메라 또는 갤러리에서 사진 선택 (최대 3장)
3. 사진을 S3에 업로드 (또는 임시 업로드)
4. POST /ai/recognize-instrument 호출
5. 백엔드:
   a. Claude Vision API에 사진 + 프롬프트 전송
   b. 응답을 파싱하여 후보 추출
   c. 마스터 DB와 매칭 (제조사, 모델, 종류)
   d. KOLAS 카테고리 자동 매핑
   e. 신뢰도 점수 계산
6. 응답: 추천값 + 후보 리스트 + 신뢰도
7. 프론트엔드: 드롭다운에 추천값 미리 선택
8. 사용자 확인/수정 후 "등록" 버튼
9. POST /instruments 호출하여 최종 저장
```

**UC-2-2: 수동 등록**
- AI 인식 실패 시 또는 사용자가 직접 입력하고 싶을 때
- 모든 필드를 빈 상태로 시작

**UC-2-3: 일괄 등록**
- 같은 모델 10대 등록할 때
- 사진 1장 + 시리얼만 각각 입력

### 2.2 입력 필드

**필수 필드**

| 필드 | 타입 | AI 자동 채움 |
|---|---|---|
| 계측기 종류 | 드롭다운 (KOLAS 568종) | ✅ |
| 제조사 | 드롭다운 (마스터 DB) | ✅ |
| 모델명 | 드롭다운 또는 텍스트 | ✅ |
| 시리얼 번호 | 텍스트 | ✅ (OCR) |
| 측정 범위 (min) | 숫자 | ✅ |
| 측정 범위 (max) | 숫자 | ✅ |
| 단위 | 드롭다운 (g, kg, mm, °C 등) | ✅ |
| 정밀도 등급 | 드롭다운 | ✅ |
| 부서 | 드롭다운 (사업장의 부서 목록) | ❌ 사용자 선택 |
| 보관 위치 | 텍스트 | ❌ |
| 사용 상태 | 드롭다운 (사용가능/교정중/수리중/사용중지/폐기) | 기본값: 사용가능 |

**선택 필드**

| 필드 | 타입 |
|---|---|
| 관리번호 | 텍스트 (없으면 자동 생성: MA-YYYYMMDD-####) |
| 취득일자 | 날짜 |
| 취득 원가 | 숫자 |
| 담당자 | 드롭다운 (사용자 목록) |
| 사용 공정 | 텍스트 |
| 메모 | 멀티라인 텍스트 |

### 2.3 비즈니스 룰

- **관리번호 자동 생성**: `MA-{YYYYMMDD}-{4자리 시퀀스}` 형식
- **사진 저장**: S3 경로 `{tenant_id}/instruments/{instrument_id}/{photo_id}.jpg`
- **신뢰도 임계값**:
  - 95% 이상: AI 추천값 기본 선택, 녹색 체크 표시
  - 80~95%: 추천값 선택되지만 "확인 필요" 노란색 표시
  - 60~80%: 후보 3개 제시
  - 60% 미만: "직접 입력 필요" 안내
- **KOLAS 카테고리 자동 매칭**: 측정기 종류가 정해지면 KOLAS 표준주기 자동 적용
- **차기 교정일 자동 계산**: 등록일 또는 마지막 교정일 + 표준주기

### 2.4 예외 처리

- 사진이 너무 흐림: "조명이 충분한 곳에서 다시 촬영해주세요"
- 명판이 안 보임: "측정기 명판이 보이도록 다시 촬영해주세요"
- AI API 오류: 수동 등록 모드로 fallback
- 모델명이 DB에 없음: "새 모델 추가" 옵션 제공 → 관리자 검토 대기

## 모듈 3: 측정기 자산 관리 (Asset Management)

### 3.1 유스케이스

**UC-3-1: 측정기 목록 조회**
- 정렬: 최근 등록순, 교정 임박순, 부서별, 종류별
- 페이지네이션: 20개씩

**UC-3-2: 검색**
- 검색어: 모델명, 시리얼, 관리번호, 부서
- 즉시 검색 (debounce 300ms)

**UC-3-3: 필터**

| 필터 | 옵션 |
|---|---|
| 사용 상태 | 사용가능 / 교정중 / 수리중 / 사용중지 / 폐기 |
| 교정 상태 | 정상 / 임박(30일 이내) / 만료 |
| 부서 | 다중 선택 |
| 종류 | 다중 선택 (KOLAS 카테고리) |
| 제조사 | 다중 선택 |
| 보유 기간 | 1년 미만 / 1~3년 / 3~5년 / 5년+ |

**UC-3-4: 측정기 상세 보기**
- 기본 정보, 사진 갤러리
- 교정 이력 타임라인
- 다음 교정일 카운트다운
- 수리 이력
- 메모

**UC-3-5: 측정기 수정**
- admin/manager만 가능
- 변경 이력 자동 기록 (audit log)

**UC-3-6: 측정기 폐기**
- 폐기 사유, 폐기일, 처리 담당자 기록
- 상태: 폐기로 전환, 검색에서 기본 제외

**UC-3-7: 측정기 일괄 작업**
- 다중 선택 → 부서 변경, 상태 변경, CSV 내보내기

### 3.2 비즈니스 룰

- 한 측정기는 한 시점에 하나의 부서/위치만 가짐
- 위치 이력은 별도 테이블로 관리 (movements)
- 상태 변경 시 자동 알림 (담당자, 부서장)
- 폐기된 측정기는 검색에서 기본 제외하지만, 이력은 영구 보존

### 3.3 예외 처리

- 권한 없는 사용자가 수정 시도: 403 Forbidden
- 사용 중인 측정기를 폐기 시도: 확인 dialog "정말 폐기하시겠습니까?"

## 모듈 4: 교정 주기 관리 (Calibration Cycle)

### 4.1 유스케이스

**UC-4-1: 교정 주기 자동 설정**
- 측정기 등록 시 KOLAS 카테고리에서 표준주기 자동 적용
- 예: 전자저울 1급 → 12개월

**UC-4-2: 교정 주기 수동 조정**
- 사업장별로 더 짧은 주기로 조정 가능 (긴 주기는 KOLAS 위반)
- 조정 사유 입력 필수

**UC-4-3: 차기 교정일 자동 계산**
- 마지막 교정일 + 주기 = 차기 교정일
- 마지막 교정 없으면: 등록일 + 주기

**UC-4-4: 교정 캘린더 조회**
- 월별, 분기별, 연간 보기
- 색상 코딩: 정상(녹색), 임박(노랑), 만료(빨강)

**UC-4-5: 교정 예산 시뮬레이션**
- 다음 3/6/12개월 교정 비용 예측
- 측정기당 평균 교정비를 사업장 설정으로 받음

### 4.2 비즈니스 룰

- 차기 교정일 < 오늘 → 상태 "만료"
- 차기 교정일 ≤ 오늘+30일 → 상태 "임박"
- 그 외 → 상태 "정상"
- 만료된 측정기로 검사 결과 입력 시도 → 경고 표시

### 4.3 KOLAS 표준 주기 매핑 (예시)

| 측정기 종류 | 표준 주기 |
|---|---|
| 전자저울 1급 | 12개월 |
| 전자저울 2급 | 12개월 |
| 디지털 캘리퍼 | 12개월 |
| 마이크로미터 | 6개월 |
| 디지털 멀티미터 | 12개월 |
| 압력계 (산업용) | 12개월 |
| 온도계 (실험실) | 12개월 |
| pH 미터 | 6개월 |

(전체 568종은 `03b_SEED_DATA.sql`에 시드 데이터로 포함)

## 모듈 5: 교정 이력 관리 (Calibration History)

### 5.1 유스케이스

**UC-5-1: 교정 이력 추가**
- 입력:
  - 교정 실시일
  - 교정 기관명
  - 교정 담당자
  - 교정 전 측정값 (As-Found)
  - 교정 후 측정값 (As-Left)
  - 기준값 대비 오차
  - 합격 여부
  - 성적서 번호
  - 성적서 PDF 첨부 (선택)

**UC-5-2: 교정 이력 조회**
- 측정기 상세 화면의 타임라인
- 그래프: 시간에 따른 As-Found 추세

**UC-5-3: 교정 이력 수정/삭제**
- 수정: 입력 실수 정정 (감사 로그 자동 기록)
- 삭제: admin만 가능, 영구 보관 위해 soft delete

### 5.2 비즈니스 룰

- 교정 합격 시: 차기 교정일 자동 갱신, 상태 "사용가능"
- 교정 불합격 시: 측정기 상태를 "사용중지" 또는 "수리중"으로 변경 안내
- 성적서 PDF는 S3에 저장, 다운로드 시 임시 URL 발급

## 모듈 6: 알림 시스템 (Notification)

### 6.1 유스케이스

**UC-6-1: 자동 알림 발송**

| 시점 | 채널 | 대상 |
|---|---|---|
| 교정일 D-30 | 앱 푸시 | 담당자 |
| 교정일 D-14 | 카톡 알림톡 | 담당자 |
| 교정일 D-7 | 카톡 + SMS | 담당자, 부서장 |
| 교정일 D-1 | 카톡 + SMS + 푸시 | 담당자 |
| 교정일 D+1 (초과) | 카톡 + SMS | 부서장, 품질책임자 |

**UC-6-2: 알림 설정**
- 사용자별 알림 채널 on/off
- 사업장별 발송 시점 커스터마이징

**UC-6-3: 알림 이력 조회**
- 발송된 모든 알림 확인
- 발송 실패 시 재시도

### 6.2 비즈니스 룰

- 카톡 알림톡은 미리 등록된 템플릿만 사용 가능
- 알림톡 실패 시 SMS로 자동 fallback
- 같은 알림 24시간 내 중복 발송 금지
- 사용자가 "오늘 보지 않기" 누르면 12시간 무음

### 6.3 알림 템플릿 예시

```
[MetroAI] 교정 만료 임박 안내

홍길동님, 다음 측정기의 교정 만료가 임박했습니다.

▸ 관리번호: MA-20240315-0023
▸ 종류: 전자저울 (CAS CBX-220H)
▸ 차기 교정일: 2026-06-14 (D-7)
▸ 부서: 품질관리팀

지금 견적 받기 → https://metroai.kr/q/abc123
```

## 모듈 7: 대시보드 및 보고서 (Dashboard & Report)

### 7.1 대시보드 위젯 (홈 화면)

**위젯 1: 핵심 지표 4개**
- 총 보유 측정기 수
- 이번 달 교정 예정 수
- 만료 임박 (30일 이내) 수
- 만료 초과 수

**위젯 2: 상태별 분포**
- 도넛 차트 (사용가능/교정중/수리중/사용중지/폐기)

**위젯 3: 부서별 보유 현황**
- 막대 차트

**위젯 4: 교정 일정 캘린더 미니뷰**
- 이번 달 일정 한눈에

**위젯 5: 최근 활동 피드**
- 최근 등록, 교정 완료, 상태 변경

### 7.2 보고서 (PDF 생성)

**보고서 1: 전체 보유 현황**
- 사업장 보유 측정기 전체 리스트
- 부서별, 종류별 집계

**보고서 2: 교정 이력 보고서**
- 특정 기간의 교정 실시 내역
- 교정 합격률, 평균 오차

**보고서 3: ISO 9001 심사 대응 보고서**
- 측정기 관리 절차 + 이력 + 증빙
- ISO 9001 7.1.5 조항 매핑

**보고서 4: KOLAS 17025 심사 대응 보고서**
- KOLAS 인증 사업장 대상
- 소급성 추적, 불확도 요소 포함

**보고서 5: 연간 교정 비용 분석**
- 측정기별 교정비, 교정기관별 비용
- 예산 대비 실적

### 7.3 비즈니스 룰

- 모든 보고서는 PDF로 생성, S3에 저장
- 보고서 생성 이력 보관 (감사용)
- 보고서에 사업장 로고 삽입 가능 (사업장 설정)

- 사업장 기본 정보 (사업자등록번호, 주소, 로고)

- 사용자 관리 (초대/삭제/권한)

- 보고서 템플릿 설정 (로고, 머릿글, 바닥글)
- 한국어/숫자 형식 (천단위 콤마 등)

## 데이터 흐름 다이어그램

```
[모바일/웹 앱]
      ↓ 사진 업로드
[API Gateway] → [S3]
      ↓ presigned URL
[AI Service] → [Claude Vision API]
      ↓ 인식 결과
[Master DB Matching]
      ↓ 후보 + 신뢰도
[모바일/웹 앱] ← 응답
      ↓ 사용자 확정
[API Gateway] → [PostgreSQL]
      ↓ 등록 완료
[Notification Scheduler] → [KakaoTalk / SMS]
```
