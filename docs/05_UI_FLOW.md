# 05. UI 화면 흐름 (UI Flow)

> 화면 = 컴포넌트 분해 + 사용자 액션 + API 호출 매핑

## 화면 구조 (Phase 1 MVP)

### 웹 화면 목록
1. 로그인 / 회원가입
2. 대시보드 (홈)
3. 계측기 목록
4. 계측기 상세
5. 신규 등록 (수동)
6. 교정 등록
7. 교정 캘린더
8. 알림 센터
9. 보고서 생성
10. 설정 (조직, 부서, 멤버, 알림)

### 모바일 화면 목록
1. 로그인
2. 홈 (대시보드 요약)
3. 사진 등록 (카메라 + AI 인식 + 확정) ⭐ 핵심
4. 계측기 목록
5. 계측기 상세
6. 알림
7. 프로필

## 화면 1: 로그인 / 회원가입

### 컴포넌트
- `LoginForm` (이메일/비밀번호)
- `RegisterForm` (다단계: 이메일·비번 → 조직정보 → 휴대폰인증)

### 사용자 액션 → API
| 액션 | API |
|---|---|
| 로그인 클릭 | `POST /auth/login` |
| 가입 완료 | `POST /auth/register` |
| 이메일 인증 | `POST /auth/verify-email` |
| 휴대폰 OTP 발송 | `POST /auth/send-otp` |
| OTP 확인 | `POST /auth/verify-phone` |

### 상태 관리
- 로그인 성공 → AccessToken localStorage + RefreshToken httpOnly Cookie
- 자동 토큰 갱신 인터셉터

```
│       [등록 완료]          │

```

### 컴포넌트
- `<CameraView>` (Expo Camera, 가이드 박스 오버레이)
- `<AiProgressDialog>` (단계별 진행 표시)
- `<RecognitionResult>`:
  - 신뢰도 배지 (색상별)
  - 드롭다운 6개 + 시리얼 텍스트필드
  - 보조정보 (부서, 위치)
  - 자동 매칭된 교정주기 표시

### 신뢰도별 UI 분기
```typescript
function RecognitionResult({ confidence }: Props) {
  if (confidence >= 90) {
    // 모든 필드 채워짐, 녹색 배지
    return <ConfirmView />;
  } else if (confidence >= 60) {
    // 후보 3~5개, 첫 번째 선택됨
    return <CandidateDropdownView />;
  } else {
    // 수동 입력 모드, 후보는 참고
    return <ManualEntryView aiCandidates={...} />;
  }
}
```

### API 호출 흐름
```
1. 사진 촬영 → 로컬 압축 (max 2MB)
2. POST /uploads/presigned → 사전서명 URL 받음
3. 직접 S3 업로드 (PUT)
4. POST /ai/recognize-instrument { photos: [s3url, ...] }
5. 결과 표시
6. 사용자 확정 → POST /instruments
7. 등록 성공 → 상세 화면 이동
```

### 오프라인 처리
- 네트워크 끊김 감지 시 사진 + 입력값 AsyncStorage 저장
- 재연결 시 큐에서 자동 처리
- 사용자에게 "오프라인 등록 3건 대기 중" 표시

```

│ 입력 방법                                │
│ ◉ 성적서 사진으로 자동 채우기              │
│ ○ 직접 입력                              │
├─────────────────────────────────────────┤
│ [성적서 사진 업로드]                       │

│ 측정점  기준값  측정값  오차              │
│ 0      0      0.0001  +0.0001          │
│ 100    100    99.998  -0.002           │
│ 200    200    199.995 -0.005           │
│                                         │
│ 측정 불확도   [±0.5mg (k=2)]  ⚠ 확인필요  │
├─────────────────────────────────────────┤

```

### API 호출
- 성적서 업로드 → `POST /uploads/presigned` → S3
- `POST /ai/recognize-certificate { fileUrl, instrumentId }`
- 결과 표시 (OCR confidence가 낮은 필드는 노란 배지)
- 저장: `POST /calibrations`
- 응답에 `nextCalibrationDate` 포함 → 측정기 상태 자동 갱신

## 화면 9: 보고서 생성

### 흐름
```
1. 보고서 종류 선택
   ◉ ISO 9001 / 17025 심사 대응
   ○ 부서별 측정기 현황
   ○ 월간 요약

2. 옵션 입력
   기간: [2025-05-15] ~ [2026-05-15]
   부서: [전체 ▾]
   포함: ☑ 측정기 목록 ☑ 교정 이력 ☑ 미준수 항목 ☐ 성적서 첨부

3. [생성하기] 클릭
   → "보고서 생성 중... (예상 30초)"

4. 완료
   [PDF 미리보기] [다운로드]
```

### API
- `POST /reports/iso-audit` → `{ reportId, status: 'generating' }`
- 폴링: `GET /reports/:id` (3초 간격, 60초까지)
- 또는 WebSocket으로 푸시 (Phase 2)
- 완료 시 `fileUrl` 제공

### `<InstrumentCard>` (목록·검색 결과 통용)
```typescript
interface InstrumentCardProps {
  instrument: Instrument;
```

### `<UrgencyBadge>`
```typescript
function UrgencyBadge({ urgency }: { urgency: Urgency }) {
  const colors = {
    overdue: 'red',
    critical: 'orange',
    warning: 'yellow',
    normal: 'gray'
  };
  // ...
}
```

### `<ConfidenceBadge>` (AI 신뢰도 표시)
```typescript
function ConfidenceBadge({ score }: { score: number }) {
  if (score >= 90) return <Badge color="green">신뢰도 {score}%</Badge>;
  if (score >= 60) return <Badge color="yellow">신뢰도 {score}%</Badge>;
  return <Badge color="red">신뢰도 {score}% (확인 필요)</Badge>;
}
```
